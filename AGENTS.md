# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## What this is

`artfinder` fetches scientific article metadata (Crossref), downloads open-access PDFs, and extracts figures/captions from those PDFs. Hobby project targeting one research field (laser-ablative nanoparticle synthesis); early stage, single maintainer, no CI.

Packaging: hatchling, `src/` layout, `requires-python >= 3.10`. Version lives in `src/artfinder/__about__.py`.

## Environment & commands

`venv/` at the repo root is the working environment (Python 3.12) with `artfinder` installed editable **from the main checkout**. **Neither `pytest` nor `hatch` is installed there** — install before running tests or type checks:

```bash
venv/bin/pip install pytest
```

Run the tests:

```bash
venv/bin/python -m pytest tests
```

Single test file / single test:

```bash
venv/bin/python -m pytest tests/test_article_pdf/test_figure_captions.py -k test_figure_captions_keys_are_labels
```

Type check (defined as a hatch env in `pyproject.toml`; needs `hatch`, or run `mypy` directly against the same targets after `venv/bin/pip install mypy pandas-stubs types-requests`):

```bash
hatch run types:check
# or
venv/bin/mypy src/artfinder tests
```

Before completing a change, type-check every edited Python file and resolve reported errors. The type check is clean; keep it that way.

**Working in a `git worktree`?** The venv's editable install points at the main checkout, so a careless invocation checks the wrong source tree and your edits look like no-ops. Tests are already handled (`pythonpath = ["src"]` in `pyproject.toml`), but single-file `mypy` runs are not. Read [docs/test_setup.md](docs/test_setup.md) before running anything from a worktree.

`tst.py` is a scratch script (gitignored via `tst*`) — safe to overwrite for quick manual checks.

## Architecture

Two largely independent halves that meet only in `api.ArtFinder`:

**1. Bibliographic metadata (Crossref)** — `api.py` → `crossref.py` → `http_requests.py` → `article.py`

- `ArtFinder` (`api.py`) is the user-facing facade: `search`, `isearch` (count only), `find_article`, `get_refs`, `download_pdf`, `get_journal_info`, `get_white_list_data`. Everything returns pandas `DataFrame`/`Series`, not objects. Only Crossref is implemented; `database="pubmed"/"all"` raises `NotImplementedError`. A Crossref query that gets no answer raises `SearchError` (exported at the top level) from `search` and `isearch`; `find_article` turns it into its empty Series with a warning.
- `Crossref` (subclass of abstract `Endpoint`) is a fluent query builder: `.search().author().filter().article().get_df()`. Note the chaining is *not* immutable — each method mutates `self.request_params` in place and then returns `self.from_self()`, a new instance built from the same shared params. Filter kwarg names use underscores and are converted to Crossref's dashes (`from_pub_date` → `from-pub-date`); values are checked by `CrossrefFilterValidator.VALIDATORS`, so adding a new filter means adding it there too.
- `Endpoint.__iter__` handles pagination: if `rows`/`sample` is set it does a single request, otherwise it cursor-paginates in `ROW_LIMIT`-sized batches. A failed request (`get` returns `{}`) raises `SearchError` in both branches — a cursor run that fails partway raises rather than returning part of the results — and so does `count`. Funder Registry lookups, made after the works arrive, only log a failure and keep the deposited name.
- `AsyncHTTPRequest` (`http_requests.py`) owns rate limiting: a semaphore for concurrency, a spacing delay derived from `CrossrefRateLimit`, and 429 handling via a shared `asyncio.Event` that pauses all in-flight tasks. Rate limits are re-read from `x-rate-limit-*` response headers on every 200.
- `FileDownloader` downloads PDFs concurrently, classifying results into `downloaded`/`restricted` (403)/`missing` (404)/`failed`, and detects HTML CAPTCHA pages served with a 200. A connection error or timeout (`ClientError`, `asyncio.TimeoutError`) lands in `failed` as `(url, exception)` for that file only; the rest of the batch carries on.

**2. PDF figure extraction** — `article_pdf.py` (the largest module) + the `*PDF` dataclasses in `dataclasses.py`

`ArticlePDF` wraps a PyMuPDF `Document`. Page-level extraction results are memoized in `KeyedDict` caches (`_text_cache`, `_drawings_cache`, `_images_cache`, `_figures_cache`) keyed by page number; document-level derived values are `@cached_property`. An image is measured by the part its clipping path leaves visible, on any side trimmed by more than `MARGIN` — a word processor can place a panel letter as a page-sized picture clipped down to the letter. Raw PyMuPDF dicts are converted into typed dataclasses (`TextBlockPDF`/`TextLinePDF`/`TextSpanPDF`, `DrawingObjectPDF`, `ImageInfoPDF`) via `from_dict`.

The figure-detection pipeline is heuristic and layered — changing an early stage silently shifts everything downstream:

0. `_get_raw_text_blocks_from_page` first puts back together a page drawn in tiles (`_join_tile_fragments`): a PDF post-processor can redraw a page as vertical strips ~53 pt wide, each clipped to itself, which cuts every line into a fragment per strip — captions come out as their first words and pass for side captions, and no block is wide enough for a paragraph. The signature is a glyph crossing a seam drawn in both strips: a fragment starting on the same baseline, *before* the previous one ends, with the character it ends in. At least `TILE_MIN_REPEATED_GLYPHS` of those mark a page as tiled (no untiled page in the corpus has one — superscript and equation-font tails abut, they do not repeat); its fragments are then joined into lines and its blocks sorted into reading order. Every other page is returned untouched. `_get_text_blocks_from_page` then strips manuscript line numbers before anything else sees the text. `_find_line_numbers` looks for a column of bare integers — narrow, aligned on one edge within 4 pt, ≥15 of them, growing down each page, with two or more on a quarter of the pages. The last two conditions are what separate line numbering from a page number in the footer (one per page) and from a numbered list (restarts its count). Left in, a line number corrupts the text of any block it was merged into and acts as a spurious nearest-neighbour for the figure bounding heuristics.
1. `_calc_paragraph_width` clusters text-block widths with DBSCAN; the heaviest cluster defines "body paragraph" width. `columns_number` and `get_paragraph_rects` are both derived from it. `_get_paragraphs_from_page` then grows each paragraph over the lines that follow it one `line_pitch` below and within its horizontal span — a paragraph's last line and the continuation lines of a hanging indent are narrower than the body, and left on their own they are taken for free-standing text and swallowed by whatever figure sits beneath them. A document can be too short for any width to repeat — a one-page SI is a title, an author list and a stack of affiliations, each a different width, all of them DBSCAN noise — and the width then comes back as `Size(0, 0, 0)`, which no block matches. Every `_is_prose` block seeds a paragraph instead; without that fallback the page has no paragraph at all, and the figure below, bounded by the nearest paragraph above its caption, grows to the top of the page and swallows the whole title block. Both degenerate cases log at debug rather than warning, because this is the handled path, not a broken document.
2. `_find_figure_captions` regex-matches `ArticlePDF.CAPTION_PATTERN` (`Fig./Figure N`, `Figure S1`, `Supplementary Figure 1`), stitches captions split across blocks/lines (a continuation line sits beneath its predecessor, one `line_pitch` below — the document's measured leading, not the height of a line, which differ in a manuscript set with extra leading — or one to `MAX_SINGLE_SPACING` line heights below, for a single-spaced caption under a 1.5- or double-spaced body; once two lines are joined, the rest must keep that caption's own spacing or be single-spaced — a word processor can close up a paragraph's last line — which keeps a double-spaced paragraph one `line_pitch` below the caption out of it. `line_pitch` pairs lines within a block *and* across consecutive horizontally overlapping blocks: a word-processor export puts nearly every line in its own block, and measuring within blocks alone leaves a single title-to-subtitle sample; a block on the same line, starting where the line ends, is the tail of that line — split off at a Greek letter or a superscript set in a symbol or equation font — and is merged into it rather than ending the caption), then keeps only captions whose first-span font properties match the document's most common — this is what separates real captions from body paragraphs starting with "Fig." — or whose label no other opening carries (a paragraph starting with `Fig. N` shares its label with the real caption).
2a. `header_rect` and `footer_rect` look for whatever occupies the same place in the top or bottom 9% of the page on at least `header_min_pages` **distinct** pages. An element takes part if it merely *reaches into* the band, ranked by its whole rectangle — a running head is often set deeper than any fixed fraction — and what keeps content out is the body text rather than a size: a header ends above every paragraph of its page, a footer starts below them all. That reads `paragraph_width`, which is why `_calc_paragraph_width` selects on prose instead of on the tables and bands found so far — `max(2, (pages - 1) // 2)`, low enough for a header printed on alternating pages of a four-page article, high enough to reject a coincidence. Counting pages rather than occurrences is what keeps a logo drawn as a stack of shapes on the title page from passing for a running header. An image must repeat its picture (its digest) as well as its place: a figure-only SI can set a different figure of the same size at the top of every page, and with no body text there nothing else keeps it out of the header. A document with no header (SI, preprints) correctly gets an empty rect, and the figure bound falls back to the top of the page.
3. `_get_figures_from_page` finds each figure from what it is made of, then pairs it with a caption — a caption below, above or beside its figure is handled by the same rule, which is what a side caption needs (Elsevier sets them ~0.6 of a column wide; no width test separates them from ordinary captions).
   - **Graphics** (`_get_figure_graphics`): visible drawings and images, less what only looks like figure content — header/footer band furniture, table ruling, rules of the page (a hairline ≥ 0.4 of the page width, judged by its paint including stroke width: a plot line can be a 1.4 pt box stroked 2.5 pt wide), decoration bleeding off the page, frames around text or beside a caption — including a frame drawn in pieces (`_frame_pieces`: hairlines and corners smaller than a figure, touching end to end, all on the border of an outline holding a caption or paragraph; BMC draws its rounded box around figure and caption as four edges and four corner arcs, and the bottom edge with its corners, just under the caption, would otherwise outbid the figure), the edges of a box fitted around a caption (AIP draws each edge as its own ~2 pt shape; one just under the caption would otherwise outbid the figure above it), anything invisible (white or fully transparent: backgrounds laid under captions and panel letters are common), and backgrounds lying mostly under a caption. An image whose blank margin runs under its caption is trimmed at the caption.
   - **Clusters** (`_get_figure_clusters_from_page`): graphics within `FIGURE_GRAPHICS_GAP` merge; then label text within `FIGURE_LABEL_GAP` joins (`_is_figure_label`: not prose — except a single-line non-body-font axis title — not in a paragraph or caption, not running matter or in the header/footer band). Body-font text above a cluster is a heading and stays out; on a two-column page text never joins a one-column cluster across the gutter (a panel letter of the next column's figure can lie nearer to this one). A cluster keeps two rects: `reach` includes hairlines and is what distances are measured from; `rect` leaves them out, as `Rect.include_rect` does everywhere else, and is what gets reported.
   - **Matching** (`_match_figures_on_page`): caption–cluster pairs are chosen together with `linear_sum_assignment` — most captions matched first, then least total distance — not nearest first: a caption between two figures is often nearer the next figure than its own. A pair separated by a paragraph or caption is invalid. Then each figure grows over unclaimed clusters within `MAX_FIGURE_PANEL_GAP` (separate panels) as long as it covers no text or other figure.
   - **Fallback**: a caption no cluster answers to (scanned page — a page-sized bitmap is no graphic — or a figure drawn in text) is bounded caption-first: bottom = caption top, top = the nearest paragraph/other caption/graphics-first figure/header above, sides narrowed by column layout (`_bound_figure_rect`, `_crosses_column_gutter`), then shrunk to its contents (`_refine_figure_rect`). On a line-numbered page the sides stop at `_line_number_gutter` — no figure can reach the strip where the numbers are printed.
   - **Carried-over figures**: a caption with nothing above it but the header and no graphics beside it, following a page that ends in graphics below its last paragraph or caption, belongs to a figure carried over from that page (`_figure_rect_on_previous_page`): the figure is bounded and stored on the previous page, the caption stays on its own. Such captions take no part in matching.
4. `extract_figures` rasterizes the resulting rects to PNG; `mark` writes an annotated copy of the PDF with detected elements outlined (useful for debugging the heuristics visually).

Every figure is keyed by its **label** — a string, not a number: `"1"` for `Figure 1`, `"S1"` for `Figure S1`, `Fig. S1`, `Figure 1S` or `Supplementary Figure 1`. `figures`, `figure_captions`, the `figure_label` parameters and the `{identifier}_fig_{label}.png` file names all use it, so a preprint carrying its supplementary information keeps `1` and `S1` apart. The caption font filter in step 2 is document-wide, but a caption in another font survives it when no other opening carries its label — this keeps both the SI captions of a combined main-text-plus-SI PDF and a lone `Fig. 2` an author typed in the body font beside a bold `Figure 1.`.

**Tables** are found the same way, from `TABLE_CAPTION_PATTERN` through the same `_find_captions`, so they inherit the caption stitching, the `1`/`S1` labels and the font filter. A word processor can put a table caption and its header row and first column in one block; `_cut_at_table_row` ends the caption at the first row of lines on one baseline more than `MIN_CELL_GAP` line heights apart (the opening line exempt — a label is often set apart from its text), and those cells go to the body. Which side of the caption the body sits on is decided per caption — both conventions are in use, roughly half the corpus each — by whichever side has the closer neighbouring block. The body then grows away from the caption while blocks follow within `MAX_CAPTION_DISTANCE` line pitches and read as cells rather than prose (`_is_prose`), staying in the caption's column and stopping at page furniture (`_running_matter_rects`, `footer_rect`); finally it grows to the horizontal rules within `MAX_CAPTION_DISTANCE` line pitches above and below its cells (on its side of the caption), and to any ruling or shading more than half inside it. `_calc_paragraph_width` selects prose blocks for the same reason — table rows cluster at a width of their own — and using `_is_prose` rather than the table rects is what keeps that from being circular.

**Article metadata** — `doi` reads the `subject` key, then the XMP packet, then page text up to the bibliography. `set_doi` writes the DOI back in the forms that reader takes (`subject`, XMP `prism:doi` and `dc:identifier` as `doi:<doi>`), replacing a DOI already there and merging into an existing packet, and saves incrementally in place when PyMuPDF allows. `title` trusts the `title` metadata only when it is printed on page 1: publishers leave file names, template placeholders and even another article's title there. Otherwise it reads the largest text in the top half of page 1, skipping running matter, a supplementary-information heading and anything under `TITLE_MIN_WORDS`; sizes within `TITLE_SIZE_RATIO` of the largest compete and the longest wins, which passes over an Elsevier journal banner set slightly larger than the title. `doi.normalize_doi` is the public parser for a DOI typed or pasted by a user and shares `DOI_PATTERN` and `strip_doi_decorations` with the PDF reader, so whatever it accepts reads back unchanged. `is_supplement` flags supplementary material by `SUPPLEMENT_DETECTION_PATTERN` on page 1: either a matching line that passes the title candidates' size and position test (`_title_candidate_font`, shared with `title`) — which keeps out an ACS main text's 8 pt "Supporting Information" link line and Springer's "Electronic supplementary material" footnote — or one of the page's first two lines at any size (an RSC ESI stamp). `SUPPLEMENT_HEADING_PATTERN`, which strips headings from titles, stays the narrower of the two. A PDF that needs a password to be read is refused in `__init__` with `ValueError`.

**Journal ranking** — `scimagojr.py` reads `data/scimagojr_*.csv` (semicolon-separated, comma decimal) and matches by title, falling back to substring match on the ISSN column. `white_list.py` queries `journalrank.rcsi.science` for the Russian journal white-list level. `ArtFinder.get_journal_info` special-cases SPIE proceedings by hardcoding the Proc. SPIE ISSNs.

## Things that will bite you

- **Everything sync wraps async in a thread.** `http_requests._execute_coro` and `white_list._run_coro_sync` both run coroutines in a fresh `Thread` + `asyncio.run` rather than calling `asyncio.run` directly. This is deliberate: the library is used from Jupyter, where an event loop is already running. Don't "simplify" it. Both hand back whatever the coroutine raised and re-raise it in the caller; keep it that way — a worker that dies without handing back a result or an error leaves the caller waiting forever (for ablation_db, a GUI worker).
- **Scalar fields are stringified and keep Crossref's case, except `doi` and `type`.** `Article.to_dict` lowercases only `article.LOWERCASE_COLUMNS` (DOIs are case-insensitive and lowercase everywhere else here; `type` is Crossref's vocabulary). Title, abstract and publisher keep their case — ablation_db stores them as `citext` — so compare them case-insensitively yourself (the SPIE check in `api.py` does). `_extract_title` and `_extract_abstract` reduce Crossref markup to plain text with `_strip_markup` (tags stripped on both sides of `html.unescape`, whitespace collapsed), which mirrors ablation_db's `_clean_title`: keep the two in step, or a title fetched here and one cleaned there stop comparing equal. The list/dict columns in `article.LIST_COLUMNS` (`authors`, `references`, `issn`, `links`, `funders`, `keywords`, `license`) stay Python objects in Crossref's case too: URLs, ISSN check digits (`X`, which SciMagoJR's ISSN match is case-sensitive about) and names depend on it. Any case folding belongs in the `_extract_*` method (keywords and reference DOIs are lowercased there). `article._format_df` parses those columns with `ast.literal_eval` only when a cell is text, as `load_csv` reads it, so `issn` is always a `list[str]`, never a scalar or NaN. Never patch the repr textually: a `.replace("none", "None")` there once turned "Iannone" into "IanNone".
- **An organisation and everyone after it are not authors.** Crossref's `author` array also lists organisations (a bare `name`, no `family`/`given`): a consortium, or, in a structured consortium byline, every section heading and institution sub-heading. The people after an organisation are its members, and the array has no marker for where a section ends, so `CrossrefArticle._drop_organisation_sections` keeps only the people before the first organisation — none, for a byline the consortium opens. Nothing is de-duplicated: two entries with the same name may be two people. Order is Crossref's, which consumers rely on as byline order.
- **Funder names come from the Funder Registry, not the deposit.** Publishers can deposit a funder's name with every non-ASCII character as `?`. `Crossref` looks up every funder with a `10.13039/` DOI at `/funders/{id}` (`_fetch_funder_registry`, cached per id on the class, failures not cached) and `CrossrefArticle` takes that entry's `name` and `alt_names`; a funder without a DOI, or whose lookup fails, keeps the deposited name. A `CrossrefArticle` built directly from a record, with no `funder_registry`, does no lookup.
- **`SciMagoJR.BASE_PATH` is `Path(__file__).parent.parent.parent / "data"`**, i.e. the repo root's `data/`. This resolves correctly only from a source checkout / editable install; the wheel ships `data/**` but the path does not point at it.
- **Status output is a custom terminal printer.** `LinePrinter`/`MultiLinePrinter` (`helpers.py`) use ANSI escapes in a terminal and IPython `DisplayHandle` under `ipykernel`. `print_status=False` on `ArtFinder` disables it. Plain `print()` in these code paths will corrupt the display.
- **Look up page furniture with `_is_running_matter(rect)`, never `_rect_key(rect) in _running_matter_rects`.** The set holds rects rounded to whole points (`RECTS_CLIP_PRECISION`); a raw key matches only when the coordinates happen to be integers, so a download stamp at x = 571.09 on every page slips through.
- **PDF tests are golden-file tests.** `tests/test_article_pdf/article_pdfs/` holds ~60 real PDFs (main texts plus supplementary-information documents from ACS, MDPI, RSC, Wiley and a Nature article bound together with its own SI) with expected output in `all_fig_captions.json` and `figure_rects.json`. Tuning any heuristic in `article_pdf.py` means re-checking those goldens — do not regenerate them wholesale to make tests pass.
- `Article` and `CrossrefArticle` use `__slots__`; `get_all_slots()` walks the MRO and defines the canonical DataFrame column set.

## Python style

- Fully annotate every function and method, including private helpers and test fixtures.
- Prefer PEP 604 unions (`X | None`), `Self` for same-class returns, and precise container types over `Any`. Narrow `Any` with `cast` as early as practical.
- Use f-strings for all interpolation, including logging calls.
- Use NumPy-style docstrings (already the convention throughout this codebase — see `api.py`, `crossref.py`): one-line summary, then `Parameters`, `Raises` (only for exceptions explicitly raised), and `Returns` (only for non-`None` returns) sections, each preceded by exactly one blank line.

## Plans

- Write any non-trivial implementation plan as a Markdown file under `docs/plans/`, not in the chat alone. State at the top of the plan that it is deleted once every step is implemented — this repo has no `docs/` folder yet, so creating one is fine when a plan first needs it.

## Git workflow

- If asked to work on more than one task at once, or the user asks for a worktree, use `git worktree` so agents don't interfere with each other's changes. Do not copy changes from a worktree back into another checkout.
- Leave changes uncommitted in the working tree unless explicitly asked to commit. The user reviews and commits manually.
- Preserve unrelated user changes. Never revert, stash, or overwrite modifications you did not make.
- Never create commits or pull requests unprompted, and do not offer to. Suggest a commit message only when asked: one concise summary line, plus up to four or five lines of additional description when useful.
